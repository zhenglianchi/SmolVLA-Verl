### 3.5 任务怎么分配：轮次 / 组 / 会话 / 任务 / 初始状态 / seed 生成

所有分配在 `run_loop_opt.sh:28-36` 一次性算好，再传给 `collect_remote.py`：

> `ROLLOUT_N` 是唯一入口（`run_loop_opt.sh` env，默认 4）；`configs/grpo_formal.yaml` 里的
> `rollout_n` 仅为备忘——本项目脚本不读取任何 YAML 配置（见 §6 注 / RESULTS.md）。

```bash
ROLLOUT_N=${ROLLOUT_N:-4}
for r in $(seq $START_ROUND $ROUNDS); do          # r = 1..15
  for i in $(seq 0 $((INSTANCES-1))); do          # i = 0..11
    task=${TASKS[$(( (r*INSTANCES + i) % 10 ))]}  # 任务轮换：每轮 12 组覆盖 10 任务（0-9 各 1-2 次）
    seed=$((20260901 + r*10000 + i*7))            # 组基础 seed
    init_state=$(( (r + i) % 10 ))                # 初始场景轮换：覆盖评估的 0-9 分布
    collect_remote.py --task-id "$task" --rollout-n "$ROLLOUT_N" \
      --group-id "r${r}_g${i}" --session-id "r${r}_s${i}" \
      --seed "$seed" --init-state-id "$init_state" ...
  done
done
```

**组（GRPO group）的构成**：一组 = 同一个 `collect_remote.py` 进程里的 4 条 episode，
共享 `(task_id, init_state_id, env_seed)`，只有 `policy_seed` 不同——这就是 reset-matched
组均值基线成立的前提（§4.2）。

**本任务实例（r=10, i=0）**：`group_id=r10_g0`、`session_id=r10_s0`、`task=0`、
`init_state=0`、`seed=20270901`；组内 4 条 episode 的 policy_seed 分别为
`20270901, 20278820, 20286739, 20294658`（`collect_remote.py:97`：seed + episode_id*7919）。

## 5. SDE 轨迹结构（chunk 级：张量形状 + mask + 逐步语义）

一次 `/predict` 产出的 `SmolVLATrajectory`（sde_sampling.py:62）：

| 字段 | 形状 | 含义 |
|---|---|---|
| `states` | `(1, 11, 50, 7)` | 11 个状态 = 初始噪声（t=1）+ 10 个去噪结果；`actions = states[:, -1]`（t=0） |
| `element_log_probs` | `(1, 10, 50, 7)` | 第 k 步的 `log p(x_{k+1} | x_k)`（对角高斯逐元素） |
| `valid_action_mask` | `(1, 50, 7)` | 动作维 mask（7 维全 True） |
| `eta` | scalar | 该 chunk 的 SDE 噪声 0.05 |

**逐步去噪（sde_sampling.py:224-250）**，SmolVLA 时间约定：t=1 是噪声、t=0 是动作：

| step | t | 操作 |
|---|---|---|
| 0 | 1.0 | `state = noise`（`model.sample_noise`，shape (1,50,7)） |
| 1 | 0.9 | `velocity = model.denoise_step(x_t, prefix_pad_masks, past_key_values=prefix_cache, timestep)` |
| 1 | 0.9 | `transition = marginal_preserving_transition(state, velocity, t=0.9, h=0.1, eta=0.05)`：`mean = x - h*(v - 0.5*g(t)^2*score)`，`std = g(t)*sqrt(h)`，`g(t)=eta*sqrt(t)` |
| 1 | 0.9 | `next_state = sample_transition(transition)`（mean + std*noise，detach） |
| 1 | 0.9 | `element_log_probs[0] = gaussian_log_prob(next, mean, std, mask, reduction="none")` |
| 2..9 | 0.8..0.1 | 同上，逐层推进 |
| 10 | 0.0（隐式） | `states[:, -1]` 即动作（`traj.actions`） |

**一个 chunk 的 logp 汇总**（`traj.log_probs`，sde_sampling.py:76）：
`mask = valid_action_mask[:, None]` 广播到 (1,10,50,7)；逐元素 logp 中被 mask 处置 0，按
`(-1,-2)` 求和 → `(1,10)`（每去噪步一个 logp）。`chunk_log_prob` 再 sum → 标量。

**训练侧的 old logp 口径**（grpo_offline.py:264）：
`stored_old = elp * vmask[:,None] * vpos[:,None,:,None]`，`sum(-1,-2)` → (1,10)。
`vpos`（valid_positions）对**非终局 chunk 全 True**；终局 chunk 只保留实际执行的
`n_exec` 个位置（§4.5 掩掉的后缀不参与）。

## 6. GRPO 数值推演（一组真实口径）

取 round 10 的组 `r10_g0`（4 条 rollout，round 总成功率 34/48=70.8%）：

### 6.1 组优势（grpo.py:19）

设该组成败 `[1, 1, 0, 1]`（3 成功 1 失败）：

```
mean = 0.75
adv  = rewards - mean = [+0.25, +0.25, -0.75, +0.25]   # 默认不除以 std（Dr.GRPO 约定）
```

若组内全成功 `[1,1,1,1]` 或全失败 `[0,0,0,0]` → **collapsed**，整组跳过（无组内信号，
只会施加 KL-to-base 项）。round 10 成功率 70.8%，按组内独立成败粗算全同概率
`0.708^4 + 0.292^4 ≈ 26%`，即 12 组中约 **8-9 组 mixed** 进入训练（与当轮
`chunks=1256` 的数量级一致）。

### 6.2 chunk 权重（grpo_offline.py:275）

`weight = 0.99^(n_chunks-1-cpos) / (n_episodes * n_chunks)`

设该组 4 条 episode 分别有 `C=[12, 15, 9, 14]` 个 chunk，mixed 组总数 8 组 → `n_episodes≈32`：
- 失败长 episode（15 chunk）不再靠 chunk 数量主导梯度（episode 均衡）；
- 同一 episode 内终局 chunk（cpos=C-1）权重最大（reward-to-go 0.99^0=1），credit 集中到
  导致成功/失败的最后一段动作。

### 6.3 GRPO 损失（grpo.py:48，每个 minibatch 一个 chunk）

```
logp    : (1,10)  当前策略重打分（Pass B，带梯度）
old     : (1,10)  采集时 stored_old（Pass A 已校验一致）
ref     : (1,10)  固定 base 重打分（Pass A，KL 锚）
log_ratio = clamp(logp - old, ±20)
ratio    = exp(log_ratio)
unclipped = ratio * adv
clipped   = clamp(ratio, 0.8, 1.2) * adv
pg_loss  = -sum(min(unclipped, clipped) * w * valid) / sum(w * valid)   # 分母只防除零
kl       = k3(ref - logp) = exp(ref-logp) - (ref-logp) - 1              # 非负
loss     = pg_loss + 0.01 * kl
```

**真实指标**（15 轮）：`ratio_mean ∈ [0.99999985, 1.00000009]` —— 首前向 ratio 恒等于 1，
说明采集与重打分数值路径完全一致；`loss≈160-340`、`chunks≈800-1600`（每轮 mixed 组数量
与 episode 长度不同导致波动）。

## 8. 关键点

- **reset-matched 组**：同组 4 条 rollout 共享 `(task, init_state_id, env_seed)`，只有策略
  噪声 seed 不同——组均值基线才有意义；初始状态按 `(r+i)%10` 轮换覆盖评估分布。
- **采集与重打分必须同一数值路径**：bf16 autocast（CUDA）+ 图像 float32 存储 +
  **逐 chunk 重打分**，三者缺一会让 ratio 偏离 1（实测批量重打分 ratio 0.5-1.65、
  bf16/fp32 差 0.34），训练静默退化。守卫：首前向 `|ratio_mean-1|>0.05` 或首 chunk
  `|rescore-stored_old|>0.05` 直接报错。
- **固定 base KL 锚定**：参考策略永远是最初的 SmolVLA-LIBERO（非轮起始策略），防策略漂移；
  代价是单轮学习幅度小（紧 KL + lr=5e-6）。
- **只训练 mixed 组 + episode 均衡加权**：全成功/全失败组跳过；chunk 权重
  `1/(E*C) * 0.99^(C-1-c)` 让失败长 episode 不主导梯度、credit 集中终局 chunk。
- **on-policy 保证 = 每轮重启 serve**：`/train` 只改磁盘权重，serve 内存里的 POLICY 必须
  重启加载，否则下一轮采集仍用旧策略。
- **终局 chunk mask**：客户端回传 `executed_steps`，服务端掩掉未执行的规划后缀动作。
- **评估口径**：确定性 ODE（非 SDE）+ seed=1000 + `n_action_steps=5`；逐任务独立进程并行
  抗偶发 CUDA 崩溃，同权重重测完全一致。
- **诚实结论**：修复上述正确性 bug 后训练不再退化（旧管道 55% → 63%），但 GRPO 未超越
  base；根因是初始状态覆盖稀疏 + 48 集/轮数据量偏少 + 100 集评估噪声 ±5%（见 `RESULTS.md`）。

> 学习入口：从一条 LIBERO 轨迹开始，看它如何变成 GRPO 的一个梯度更新，再如何覆盖权重。
> 重点在 **serve 的 session 如何记录轨迹、离线训练如何重打分并计算 GRPO 损失**。

## 1. 端到端数据流（学习主线）

```
① 环境采集（collect_remote.py）        ② 服务端记录（serve_smolvla.py）
   LIBERO 仿真环境                        SESSIONS[sid][ep_id]["chunks"][chunk_id]
   └─ 每 chunk：obs → POST /predict ───▶   └─ batch(CPU,float32) + SDE states + logp + mask
   └─ 执行 action_steps 步               POST /finish ─▶ success / executed_steps
   └─ 组内 4 条 rollout 同初始场景            （终局 chunk 按实际执行步数 mask）
                                                    │
③ 离线训练（grpo_offline.train_from_sessions） ④ 权重夹（run_loop_opt.sh）
   └─ 逐 chunk 重打分（校验 ratio≈1）  ─▶   └─ 保存 model.safetensors（覆盖）
   └─ 组优势 → GRPO 损失 → AdamW           └─ best 备份 smolvla_best
   └─ 只更新 mixed 组（全成功/全失败跳过）           │
                                                    ▼
⑤ on-policy 下一轮：重启 serve，用最新权重继续采集（POST /clear 清 session）
```

## 2. 各端源码定位（重点）

### 2.1 采集端 `scripts/collect_remote.py`

| 函数 | 作用 |
|---|---|
| `main()` | 单实例循环：起 LIBERO 环境 → 4 条 episode（同 task/init_state/env_seed，仅策略噪声 seed 不同） |
| `run_one(episode_id, seed)` | 单条 rollout：每 chunk 调 `/predict`，执行 `action_steps` 步，失败提前终止 |
| `_success_from_step` | 从 `final_info` 判断 episode 是否成功（兼容 dict / list 两种格式） |
| `_img_b64` / `_conv` | 图像/状态编码，POST 到 serve |

**组内同场景（reset-matched）**：一个 group 的 4 条 rollout 共享
`(task, init_state_id, env_seed)`，只有策略噪声 seed 不同——这是 GRPO 组均值基线成立的前提。

### 2.2 服务端 `scripts/serve_smolvla.py`

| 端点 | 作用 |
|---|---|
| `POST /predict` | 预处理 obs → `sde_sampling.sample_sde_chunk` 采样动作 chunk + log-prob → 记录到 `SESSIONS` → 返回 actions |
| `POST /finish` | 标记 episode 成功与否；用 `executed_steps` 掩掉终局 chunk 未执行的规划后缀 |
| `POST /train` | 调 `grpo_offline.train_from_sessions` 做 1~N 步 GRPO，保存权重到 `SAVE_DIR` |
| `POST /clear` | 清空 `SESSIONS` / `GROUP_RESULTS`（每轮训练后调用） |
| `GET /stats` / `GET /health` | 监控 |

**记录的 chunk 数据结构**（训练直接消费）：

| 字段 | 含义 |
|---|---|
| `batch` | 预处理后的 obs（CPU、float32，保证重打分与采集数值路径一致） |
| `states` / `element_log_probs` | SDE 去噪轨迹状态与逐元素 log-prob |
| `valid_action_mask` / `valid_positions` | 哪些动作位参与损失（终局 chunk 掩掉未执行部分） |
| `eta` | 该 chunk 的 SDE 噪声（采集与训练必须一致） |

### 2.3 SDE 采样与重打分 `src/smolvla_verl/models/smolvla/sde_sampling.py`

| 函数 | 作用 |
|---|---|
| `prepare_policy_prefix` | 用 SmolVLM2 视觉语言模型构建 prefix KV cache（避免每 chunk 重复编码） |
| `sample_sde_chunk` | 从噪声按边缘保持 SDE 去噪 10 步，得到动作 chunk + log-prob |
| `recompute_log_probs` | **逐 chunk 重打分**：训练时用最新权重重算 logp（old_log_prob），与采集 logp 比对 |
| `rollout_autocast` | bf16 autocast 上下文，保证采集/重打分同一数值路径 |

### 2.4 GRPO 损失 `src/smolvla_verl/models/smolvla/grpo.py`

| 函数 | 作用 |
|---|---|
| `compute_group_advantages` | 组内成功率减均值（不除以标准差，Dr.GRPO 约定） |
| `k3_kl_estimate` | 与固定 base 参考策略的非负 KL（防漂移锚定） |
| `grpo_loss` | 逐去噪步 clipped ratio × 优势 + KL；按 episode 均衡加权，分母只防除零（修复点） |

## 3. 为什么 ODE 要改成 SDE（算法关键）

SmolVLA 原生推理是**确定性 ODE 流匹配**（10 步去噪解出整个动作 chunk），没有 log-prob，
无法直接算策略梯度。改造思路（FlowVLA-RL，arXiv:2505.05470）：

1. 把确定性去噪换成带噪声的随机转移：`p(x_{t-h}|x_t)` 是高斯，有**闭式 log-density**；
2. 各噪声层的**边缘分布保持不变**，所以动作质量与 ODE 版本等价；
3. 于是每条 rollout 有逐去噪步 log-prob → 可以算 ratio → GRPO 更新。

实现见 `sde.py`：`score_from_velocity` / `diffusion_scale` / `marginal_preserving_transition` /
`gaussian_log_prob`。

## 4. 训练主循环 `src/smolvla_verl/trainer/grpo_libero.py`

（在线全流程脚本实际走 `run_loop_opt.sh` + serve；`grpo_libero.py` 是等价的多进程版本）

- `RolloutWorker.collect_episode`：起 LIBERO env → 逐 chunk 采样 → 返回 episode 数据
- `build_trainable` / `build_reference`：learner 从**与首轮 rollout 相同的权重**起步（resume 一致性修复）
- 每轮：任务轮换 `(rnd*groups+g) % 10`、初始状态轮换 `(rnd+g) % 10` → 4 条组内同场景 rollout
- mixed 组才更新：全成功/全失败组无组内信号，跳过

## 5. 训练脚本编排 `scripts/run_loop_opt.sh`

```
for r in 1..ROUNDS:
  12 实例并行 collect_remote（task/init_state 轮换，4 rollout/实例）→ 48 集/轮
  统计成功率 → POST /train(lr=5e-6, steps=1, batch=32, chunk_discount=0.99)
  POST /clear → 更新 best 备份 → 重启 serve（加载最新权重）→ 下一轮
STOP_AT 时间截止 / ROUNDS 控制轮数 → 自动进入官方评估
```

## 1. verl-vla 是什么

verl-vla 是 [verl](https://github.com/verl-project/verl) 之上的 **VLA post-training 框架**：
把「数据采集 → 微调 → 强化学习」统一到一套执行架构里。模型、环境、训练算法各自独立接入，

## 5. 关键概念速记

- **Flow matching**：动作不是自回归生成的，而是从噪声按 ODE 去噪 10 步解出整个动作 chunk。
- **SDE 边缘保持**：把确定性去噪换成带噪声的随机转移，噪声边缘分布不变，但每个转移有了
  `log p(x_{t-h}|x_t)` 的闭式解 —— 这是能算策略梯度（GRPO）的前提。
- **GRPO**：同一初始场景采样 G 条 rollout，组内成功率的均值做基线，减去基线后的二进制奖励
  不除以标准差（Dr.GRPO），再乘 clipped ratio + KL 惩罚。全成功/全失败组没有信息量，跳过。
- **KL 锚定**：固定 base 参考策略算 KL，防止策略漂移太远（代价是学习幅度小）。
- **on-policy**：每轮必须用最新权重重新采集，否则 log-prob 对不上，训练退化。

## 6. 本次踩过的坑（调试时先查这里）

1. 批处理重打分会让 `valid_positions` 错位 → 必须逐 chunk 重打分，并校验 ratio ≈ 1（偏差 >0.05 报错）。
2. 同组 rollout 必须 reset-matched 同初始场景，否则组均值基线没意义。
3. 终局 chunk 要按实际执行步数 mask 掉未执行的动作。
4. 采样 SDE 噪声 `eta` 与评估的确定性 ODE 口径要尽量一致（0.05）。
5. 每轮训练后必须重启 serve 让 rollout worker 加载最新权重。

## 7. 推荐的后续实验

- 采集初始状态随机化（0-9 全覆盖且每状态多采样）——当前最大嫌疑
- 每组 rollout 4 → 8，放宽 KL / 提高 lr（先看 ratio_mean 是否稳定在 1 附近再放）
- 评估 100 集噪声 ±5%，想看到统计显著差异需要 200+ 集或多次运行取均值
