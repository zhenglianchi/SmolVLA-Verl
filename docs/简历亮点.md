# 简历亮点

## 项目简介

基于 verl/verl-vla 构建 **SmolVLA（0.45B 流匹配 VLA）在线强化学习（FlowGRPO）训推平台**：
本地采集 LIBERO 轨迹 → 云端 serve 记录 token/chunk 级 log-prob → 离线 GRPO 训练 →
单权重夹覆盖 → 官方协议自动评估。把"没有 log-prob 的 flow-matching 策略"改造成
可训练的 GRPO 策略（ODE→SDE 边缘保持），并定位修复多个会导致"跑一天没效果"的
RL 正确性 bug。LIBERO-Spatial 官方协议（10 任务 × 10 trials）：
**Base 63.0% / GRPO 63.0%**，修复后训练不再退化（旧管道 55% → 63%）。

## 亮点一：FlowGRPO 算法落地（flow-matching VLA 的 RL 化）

SmolVLA 原生是确定性 ODE 流匹配采样（10 步去噪解出动作 chunk），**没有 log-prob，
无法直接算策略梯度**：

- 按 FlowVLA-RL（arXiv:2505.05470）做 **边缘保持 SDE 改造**：随机转移 `p(x_{t-h}|x_t)`
  是高斯、有闭式 log-density，各噪声层边缘分布与 ODE 一致 → 动作质量不变，但每条
  rollout 有逐去噪步 log-prob
- 实现 critic-free **GRPO**：reset-matched 同场景组均值基线 + 二进制成功奖励 +
  固定 base 参考 KL 锚定 + 逐去噪步 clipped ratio
- 在 verl-vla 注册 SmolVLA 架构（builder + 模型包 + trainable wrapper），补丁幂等可重放

## 亮点二：RL 正确性排障（"跑一天没效果"根因定位）

首版训练后官方指标从 63% 退到 55%，逐项排查定位并修复 5 类正确性 bug：

- **批处理重打分破坏 log-prob**：整批重打分时 mask/长度错位 → old_log_prob 与采集不一致
  → ratio 漂移训练退化；改为**逐 chunk 重打分** + 数值一致性守卫（ratio 偏离 >0.05 直接报错）
- **组内不同初始场景**：同组 rollout 必须 reset-matched，否则组均值基线无意义
- **终局 chunk mask**：规划的 50 步只执行 5 步，未执行后缀必须掩掉
- **GRPO 加权分母 bug**：分母被 `clamp_min(1.0)` 放大梯度 ~1/Σw 并污染 ratio 指标
- **训练目标**：只更新 mixed 组（全成功/全失败组无信号），chunk 按 episode 均衡加权

修复后 15 轮正式训练 ratio_mean 全程稳定在 1.000000，采集成功率无退化，官方指标
**63.0%（重测 ×2 一致）**，验证了修复有效性。

## 亮点三：训推分离平台化工程

- **架构**：本地（8GB）只做采集/推理 ↔ 云端（RTX 4090）serve + 训练；HTTP 端点
  （predict/finish/train/clear）承载数据流，12 实例并行在线 rollout
- **on-policy 工程**：每轮训练后重启 serve 加载最新权重；任务/初始状态轮换覆盖评估分布；
  断点续训 + 时间截止自动停 + 最佳权重备份 + 看门狗
- **评估工程**：官方协议逐任务独立进程并行（`eval_parallel.sh`），单任务失败可重跑；
  `n_action_steps=5` 与采集口径一致；同权重 seed=1000 确定性重测 ×2 完全一致

## 面试表述建议（诚实版）

- 不要说"提升到 63%"，说"**修复退化 + 持平 base**"：先跑通、再谈收益，排障过程本身是亮点
- 数字口径：Base 63.0%（重测 ×2）/ GRPO-15轮 63.0%（重测 ×2）/ 旧管道 R16 55.0%
- 如果被问"为什么没提升"：初始状态覆盖稀疏 + 48 集/轮数据量少 + 紧 KL 防退化 +
  100 集评估噪声 ±5%，这是合理的下一步方向，不是失败
