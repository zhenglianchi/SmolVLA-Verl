# 数据流与源码导读

> 学习入口：从一条 LIBERO 轨迹开始，看它如何变成 GRPO 的一个梯度更新，再如何覆盖权重。
> 重点在 **serve 的 session 如何记录轨迹、离线训练如何重打分并计算 GRPO 损失**。

## 1. 端到端数据流（学习主线）

```
① 环境采集（collect_remote.py）        ② 服务端记录（serve_smolvla.py）
   LIBERO 仿真环境                        SESSIONS[sid][ep_id]["chunks"][chunk_id]
   └─ 每 chunk：obs → POST /predict ───▶   └─ batch(CPU) + SDE states + logp + mask
   └─ 执行 action_steps 步               POST /finish ─▶ success / executed_steps
   └─ 组内 4 条 rollout 同初始场景            （终局 chunk 按实际执行步数 mask）
                                                    │
③ 离线训练（grpo_offline）              ④ 权重夹（run_loop_opt.sh）
   train_from_sessions()                   /home/ubuntu/runs/smolvla_grpo
   └─ 逐 chunk 重打分（校验 ratio≈1）  ─▶   └─ 保存 model.safetensors
   └─ 组优势 → GRPO 损失 → AdamW           └─ best 备份 smolvla_best
   └─ 只更新 mixed 组（全成功/全失败跳过）           │
                                                    ▼
⑤ on-policy 下一轮：重启 serve，用最新权重继续采集（POST /clear 清 session）
```

## 2. 各端源码定位（重点）

### 2.1 采集端 `scripts/collect_remote.py`

| 函数 | 作用 |
|---|---|
| `main()` | 单实例循环：起 LIBERO 环境 → 4 条 episode（同 task/init_state/env_seed，仅策略噪声 seed 不同） |
| `run_one(episode_id, seed)` | 单条 rollout：每 chunk 调 `/predict`，执行 `action_steps` 步，失败提前终止 |
| `_success_from_step` | 从 `final_info` 判断 episode 是否成功（兼容 dict / list 两种格式） |
| `_img_b64` / `_conv` | 图像/状态编码，POST 到 serve |

**组内同场景（reset-matched）**：一个 group 的 4 条 rollout 共享
`(task, init_state_id, env_seed)`，只有策略噪声 seed 不同——这是 GRPO 组均值基线成立的前提。

### 2.2 服务端 `scripts/serve_smolvla.py`

| 端点 | 作用 |
|---|---|
| `POST /predict` | 预处理 obs → `sde_sampling.sample_sde_chunk` 采样动作 chunk + log-prob → 记录到 `SESSIONS` → 返回 actions |
| `POST /finish` | 标记 episode 成功与否；用 `executed_steps` 掩掉终局 chunk 未执行的规划后缀 |
| `POST /train` | 调 `grpo_offline.train_from_sessions` 做 1~N 步 GRPO，保存权重到 `SAVE_DIR` |
| `POST /clear` | 清空 `SESSIONS` / `GROUP_RESULTS`（每轮训练后调用） |
| `GET /stats` / `GET /health` | 监控 |

**记录的 chunk 数据结构**（训练直接消费）：

| 字段 | 含义 |
|---|---|
| `batch` | 预处理后的 obs（CPU、float32，保证重打分与采集数值路径一致） |
| `states` / `element_log_probs` | SDE 去噪轨迹状态与逐元素 log-prob |
| `valid_action_mask` / `valid_positions` | 哪些动作位参与损失（终局 chunk 掩掉未执行部分） |
| `eta` | 该 chunk 的 SDE 噪声（采集与训练必须一致） |

### 2.3 SDE 采样与重打分 `verl-vla/src/verl_vla/models/smolvla/sde_sampling.py`

| 函数 | 作用 |
|---|---|
| `prepare_policy_prefix` | 用 SmolVLM2 视觉语言模型构建 prefix KV cache（避免每 chunk 重复编码） |
| `sample_sde_chunk` | 从噪声按边缘保持 SDE 去噪 10 步，得到动作 chunk + log-prob |
| `recompute_log_probs` | **逐 chunk 重打分**：训练时用最新权重重算 logp（old_log_prob），与采集 logp 比对 |
| `rollout_autocast` | bf16 autocast 上下文，保证采集/重打分同一数值路径 |

### 2.4 GRPO 损失 `verl-vla/src/verl_vla/models/smolvla/grpo.py`

| 函数 | 作用 |
|---|---|
| `compute_group_advantages` | 组内成功率减均值除以标准差（无 reward model，纯二进制成功奖励） |
| `k3_kl_estimate` | 与固定 base 参考策略的 KL（防漂移锚定） |
| `grpo_loss` | 逐去噪步 clipped ratio × 优势 + KL；按 episode 均衡加权，分母不 clamp（修复点） |

## 3. 为什么 ODE 要改成 SDE（算法关键）

SmolVLA 原生推理是**确定性 ODE 流匹配**（10 步去噪解出整个动作 chunk），没有 log-prob，
无法直接算策略梯度。改造思路（FlowVLA-RL，arXiv:2505.05470）：

1. 把确定性去噪换成带噪声的随机转移：`p(x_{t-h}|x_t)` 是高斯，有**闭式 log-density**；
2. 各噪声层的**边缘分布保持不变**，所以动作质量与 ODE 版本等价；
3. 于是每条 rollout 有逐去噪步 log-prob → 可以算 ratio → GRPO 更新。

实现见 `sde.py`：`score_from_velocity` / `diffusion_scale` / `marginal_preserving_transition` /
`gaussian_log_prob`。

## 4. 训练主循环 `src/smolvla_verl/trainer/grpo_libero.py`

（在线全流程脚本实际走 `run_loop_opt.sh` + serve；`grpo_libero.py` 是等价的多进程版本）

- `RolloutWorker.collect_episode`：起 LIBERO env → 逐 chunk 采样 → 返回 episode 数据
- `build_trainable` / `build_reference`：learner 从**与首轮 rollout 相同的权重**起步（resume 一致性修复）
- 每轮：任务轮换 `(rnd*groups+g) % 10`、初始状态轮换 `(rnd+g) % 10` → 4 条组内同场景 rollout
- mixed 组才更新：全成功/全失败组无组内信号，跳过

## 5. 训练脚本编排 `scripts/run_loop_opt.sh`

```
for r in 1..ROUNDS:
  12 实例并行 collect_remote（task/init_state 轮换，4 rollout/实例）→ 48 集/轮
  统计成功率 → POST /train(lr=5e-6, steps=1, batch=32, chunk_discount=0.99)
  POST /clear → 更新 best 备份 → 重启 serve（加载最新权重）→ 下一轮
STOP_AT 时间截止 / ROUNDS 控制轮数 → 自动进入官方评估
```
